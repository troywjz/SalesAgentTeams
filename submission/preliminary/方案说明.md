# 初赛方案说明

## 1. 场景与价值

办公技能培训咨询通常需要同时判断真实工作场景、客户基础、销售阶段、课程与价格事实、数据安全和交易边界。单一大模型容易出现信息准确但缺少下一步动作、承诺过度或无法解释的问题。SalesAgentTeams 将这些职责显式拆分，使每个 Worker 有清晰输入输出和可验证边界。

## 2. 六 Worker 协作

1. `memory_worker` 读取授权历史摘要。
2. `intent_worker` 识别意图、购买意愿和情绪。
3. `sop_worker` 判断销售阶段与下一步动作。
4. `knowledge_worker` 从授权知识快照检索事实和引用。
5. `conversation_worker` 汇总信息并生成单问题推进式草稿，同时作为 Team Leader 协调团队。
6. `safety_worker` 在客户可见回复发送前审核、改写或转人工。
7. `memory_worker` 沉淀本轮允许保存的记忆。

AgentTeams Manager 只与 Team Leader 交互，Team Leader 再协调团队内 Worker。每一步通过统一的 `task_id`、`conversation_id`、`turn_id` 和结构化状态传递，结果带有 Worker、Skill 版本、证据引用、失败状态和交接信息。

## 3. Skill 设计

六个业务 Worker 分别使用：

- `intent-classification`
- `sop-decision`
- `knowledge-grounding`
- `reply-drafting`
- `safety-review`
- `memory-update`

所有 Worker 共同使用 `evidence-handoff`。加上 Team Leader 协调、离线评估和热力图能力，共 10 个 Skill。每个 Skill 采用 YAML front matter 和 Markdown 契约，包含版本、目的、输入、输出、触发条件、依赖工具、失败处理、安全边界、复用价值、多 Agent 关系和验证方法。

## 4. MCP 设计

### 销售 Agent Bridge MCP

提供六个角色受限工具：

`run_intent_agent`、`run_sop_agent`、`run_knowledge_agent`、`run_conversation_agent`、`run_safety_agent`、`run_memory_agent`。

MCP 服务端会校验 Worker 与工具的对应关系，避免 Worker 越权调用。服务支持 stdio 和 Streamable HTTP 两种运行方式。

### 评估与热力图 MCP

提供：

- `run_offline_evaluation`
- `score_offline_evaluation`
- `generate_3d_heatmap`

热力图使用真实 `评分明细.csv`，横轴为对话回合，纵轴为 A/C/R/P/F 指标，纵深和颜色为 0～1 评分。缺少人工评分、字段错误或数值越界时直接失败，不生成虚假数据。

## 5. 开源运行路径

本地 Web 使用确定性演示模型验证六 Worker 链路，只有独立 PostgreSQL 需要一个轻量容器；MCP 模式通过 Docker Compose 暴露 HTTP 服务；AgentTeams 模式通过官方 CRD 清单创建六个 Worker、一个 Team 和一个 Manager。比赛端固定使用 `18100` 和 `15432/sales_agent_demo`，不会访问原项目 `8000`、原会计数据库或历史会话。

## 6. 工程验证与成本控制

- 公开模板默认 `DEMO_MODE=false`、`LLM_PROVIDER=deepseek`，填写一个 DeepSeek Key 即可同时启动 Web 与 AgentTeams；启动门禁禁止密钥缺失时静默降级为本地模型。
- 自动化测试通过进程级变量强制 `DEMO_MODE=true`、`LLM_PROVIDER=demo`，不产生真实 API 调用。
- Supervisor 对强制转人工和简单寒暄走确定性路径，只在需要时调用完整 Agent 链。
- 真实模型模式默认最多尝试一个供应商，推理 token 预留为 0，各 Agent 输出上限按 JSON 契约收紧。
- 官方 DeepSeek V4 直连对结构化 Agent 请求启用 JSON Output 并关闭默认思考模式，避免推理内容耗尽短 JSON 的输出上限；其他兼容网关不发送该供应商私有参数。
- `check_competition_readiness.py` 自动检查 Worker、Skill、MCP、数据隔离、正式展示配置门禁和提交材料。
- `check_open_source.py` 检查追踪文件、私有路径和明显密钥。
